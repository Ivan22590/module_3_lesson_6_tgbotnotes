Ты — опытный Python-разработчик, который пишет понятный, аккуратный и доступный код для новичков.

Задача:
Создай минимальный рабочий проект Telegram-бота для командной работы над задачами. Бот должен позволять разным пользователям добавлять задачи в общий список, просматривать список задач и выгружать его в CSV-файл.

Цель проекта:
Получить простой, но полноценный пример командного Telegram-бота, где все задачи хранятся в общей базе данных, а управление происходит через команды и кнопки.

Технологии:
- Python 3.11+
- aiogram 3.x
- SQLite через aiosqlite для асинхронной работы с базой данных
- python-dotenv для загрузки токена из файла .env
- aiogram FSM для ожидания текста задачи после нажатия кнопки добавления
- Запуск через long polling, без webhook
- Без ORM, только простые SQL-запросы

Основной сценарий:
- Все пользователи видят общий список задач.
- Любой пользователь может добавить задачу.
- Авторизация не нужна.
- Каждый пользователь добавляет задачу от своего имени.
- Задачи хранятся в базе данных.
- Основной интерфейс должен быть через кнопки.
- Команды тоже должны работать как дополнительный способ управления.

Интерфейс бота:
- Используй обычную Reply-клавиатуру, без inline-кнопок, чтобы код оставался простым.
- После команды /start бот должен показывать главное меню с кнопками:
  - "➕ Добавить задачу"
  - "📋 Список задач"
  - "📄 Экспорт CSV"
- Кнопки должны быть крупными и удобными.
- Используй resize_keyboard=True.
- Тексты кнопок вынеси в константы, чтобы не дублировать их в коде.
- Также поддержи команды:
  - /start
  - /add
  - /list
  - /list_csv
  - /cancel

Логика добавления задачи:
- Пользователь нажимает кнопку "➕ Добавить задачу" или отправляет команду /add.
- После этого бот не сохраняет задачу сразу.
- Бот переводит пользователя в режим ожидания текста задачи с помощью FSM.
- Бот отвечает:
  "Отправьте текст задачи одним сообщением."
- На время ввода текста бот показывает отдельную клавиатуру с кнопкой:
  "❌ Отмена"
- Следующее текстовое сообщение пользователя должно восприниматься как текст задачи.
- Если пользователь отправляет кнопку "❌ Отмена" или команду /cancel, добавление задачи отменяется.
- После отмены бот должен:
  - очистить состояние;
  - вернуть главное меню;
  - ответить: "Добавление задачи отменено."
- Если пользователь прислал текст задачи:
  - бот сохраняет задачу в базу;
  - очищает состояние;
  - возвращает главное меню;
  - отвечает: "Задача добавлена."
- Если пользователь во время ожидания текста отправил не текстовое сообщение, например фото, стикер или голосовое, бот должен ответить:
  "Пожалуйста, отправьте текст задачи текстовым сообщением."
- Пустой текст задачи сохранять нельзя.
- Если текст задачи содержит только пробелы, бот должен попросить отправить корректный текст задачи.

Команды и кнопки:

1. /start
   - Приветствует пользователя.
   - Кратко объясняет, что делает бот.
   - Показывает главное меню с кнопками:
     - "➕ Добавить задачу"
     - "📋 Список задач"
     - "📄 Экспорт CSV"

2. /add или кнопка "➕ Добавить задачу"
   - Запускает процесс добавления задачи.
   - Переводит пользователя в состояние ожидания текста задачи.
   - Показывает кнопку "❌ Отмена".
   - Не сохраняет задачу сразу.
   - Даже если пользователь отправил /add с текстом в том же сообщении, основной сценарий должен быть таким: бот просит отправить текст задачи следующим сообщением.

3. /list или кнопка "📋 Список задач"
   - Выводит все задачи из общего списка.
   - Формат вывода должен быть простым и читаемым.
   - Каждая задача должна показывать:
     - порядковый номер;
     - текст задачи;
     - автора;
     - дату создания.
   - Если задач нет, бот должен ответить:
     "Задач пока нет."
   - После вывода списка бот должен вернуть или оставить главное меню.

4. /list_csv или кнопка "📄 Экспорт CSV"
   - Формирует CSV-файл со всеми задачами.
   - Отправляет этот файл пользователю как документ.
   - В CSV должны быть колонки:
     id, text, user, created_at
   - Кодировка файла: UTF-8 with BOM, то есть utf-8-sig, чтобы файл нормально открывался в Excel.
   - Разделитель: запятая.
   - Если задач нет, бот не должен отправлять пустой файл. Вместо этого нужно ответить:
     "Задач пока нет, поэтому нечего экспортировать."
   - После экспорта бот должен вернуть или оставить главное меню.

5. /cancel или кнопка "❌ Отмена"
   - Отменяет текущее действие, если пользователь находится в состоянии добавления задачи.
   - Очищает состояние.
   - Возвращает главное меню.
   - Если отменять нечего, бот может ответить:
     "Сейчас нет активных действий для отмены."

Требования к FSM:
- Используй aiogram.fsm.state.StatesGroup и State.
- Создай класс состояний, например:
  class AddTaskStates(StatesGroup):
      waiting_for_text = State()
- Dispatcher должен быть создан с хранилищем состояний:
  MemoryStorage
- Состояние должно устанавливаться при нажатии кнопки добавления или команде /add.
- Состояние должно очищаться после:
  - успешного сохранения задачи;
  - отмены добавления;
  - завершения сценария.
- Обработчик текста задачи должен срабатывать только в состоянии ожидания текста.
- Обработчик отмены должен корректно работать и по команде /cancel, и по кнопке "❌ Отмена".

Требования к базе данных:
- Файл базы данных: tasks.db
- При первом запуске база данных должна создаваться автоматически.
- Таблица должна называться tasks.
- Структура таблицы:
  id INTEGER PRIMARY KEY AUTOINCREMENT
  text TEXT NOT NULL
  user TEXT NOT NULL
  created_at TEXT NOT NULL
- Для всех запросов используй параметризованные выражения, чтобы избежать SQL-инъекций.
- Для даты создания задачи используй:
  datetime.now(timezone.utc).isoformat()
- В качестве автора задачи используй:
  - message.from_user.username, если он есть;
  - иначе message.from_user.full_name.
